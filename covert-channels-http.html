Covert Channels: HTTP

Data skjult i store/små forbogstaver på HTTP-headere.

ForensicsHaaukins CTF
🎓 Prøv selv først. Trinene viser metoden; det konkrete flag ligger i en sammenklappelig spoiler nederst. Haaukins-flag er ofte per-instans, så det er fremgangsmåden der tæller.

Hvad går opgaven ud på?

Alle tre opgaver løses på samme capture.pcap. Start altid med protokol-hierarkiet, og saml bits/bytes i kronologisk rækkefølge:

tshark -r capture.pcap -q -z io,phs

HTTP-headernavne er case-insensitive (RFC 2616 §4.2), så stort/lille forbogstav kan bære 1 bit pr. header uden at ændre requesten. 8 faste headers = 1 byte pr. request.

Trin for trin

tshark -r capture.pcap -Y 'http.request && ip.dst==100.117.87.84' -T text -V   # se casing

De 20 requests bruger alle de samme 8 headers i samme rækkefølge, kun casingen varierer. Noget i stil med denne liste for én request (bemærk at Accept-Encoding og upgrade-insecure-requests har forskellig casing):

user-agent: ...
Accept-Encoding: ...
accept: ...
connection: ...
Host: ...
upgrade-insecure-requests: 1
cache-control: ...
accept-language: ...

For hver request: stort forbogstav = 1, lille = 0, i headernes faste rækkefølge, giver 8 bit, altså ét ASCII-tegn. 20 requests = 20 bytes:

python3 -c "
headers_order = ['user-agent','Accept-Encoding','accept','connection',
                  'Host','upgrade-insecure-requests','cache-control','accept-language']
bits = ''.join('1' if name[0].isupper() else '0' for name in headers_order)
print(chr(int(bits, 2)))"   # ét tegn; gentag for hver request og sæt sammen i rækkefølge

Faldgrube: filtrér ikke på ordet "Request" i tsharks tekstoutput. Headeren upgrade-insecure-requests indeholder selv "request" og matcher ved et uheld.

🚩 Vis løsning & eksempel-flag

Flag: HKN{3nc0d3d_1n_c4ps}

Hvad du har lært

  • Covert channels bor i felter der kan variere frit — her header-casing.
  • Opgaveteksten hinter om feltet (’RFC 2616 §4.2’).
